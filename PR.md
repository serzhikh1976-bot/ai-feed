# PROJECT SUMMARY — AI Feed Generator

*Останнє оновлення: 18 серпня 2026*

---

## 1. Загальна мета проєкту

Сервіс приймає файл постачальника (Excel/CSV), автоматично визначає колонки, обробляє до 20 товарів, збагачує їх через ШІ (OpenAI або Gemini) та формує XML-фід для маркетплейсів Prom.ua / Rozetka у форматі YML.

---

## 2. Поточний статус

✅ **Що вже працює:**
- Завантаження файлів `.xlsx`, `.xls`, `.csv` через веб-інтерфейс.
- Автоматичне визначення колонок (`sku`, `name`, `price`, `image`, `description`, `availability`) за ключовими словами або евристикою.
- Асинхронна обробка (завдання у фоновому режимі з опитуванням статусу).
- Генерація контенту через ШІ:
  - Назва (формула: тип + бренд + ключові властивості)
  - Опис (українською, з HTML-структурою)
  - Параметри (`params`)
  - SEO-поля (`html_title`, `html_description`, `search_queries`)
- Вибір категорії зі справочника Prom.ua (`prom_categories.xls`):
  1. ШІ обирає верхній рівень зі списку 58 категорій.
  2. Алгоритм пошуку шукає найкращу підкатегорію всередині цієї гілки за ключовими словами.
- Підтримка двох ШІ-провайдерів (OpenAI gpt-4o-mini, Gemini 2.5 Flash) та заглушки (`mock`) для тестування.
- Формування XML-фіду з товарами (статуси `success` / `warning`).
- Інтерфейс користувача з полями:
  - Контекст файлу
  - Бренд (жорстке завдання для всіх товарів)
  - Тип товару
  - Особливі вимоги до опису

❌ **Що недороблено / обмеження:**
- **Ручний вибір категорії** – немає UI, ШІ обирає сам (іноді помиляється).
- **Гнучкий маппінг колонок** – зараз тільки 6 жорстких полів. Додаткові колонки (колір, розмір, модель, вага) не передаються ШІ.
- **Артикул у назві** – ШІ додає артикул у назву, хоча має бути лише у `<vendorCode>`.
- **Категорії для одягу** – ШІ плутає дорослий і дитячий одяг через відсутність чіткої категорії «Одяг для дорослих».
- **Російська мова у фіді** – Prom.ua не підтримує імпорт SEO-полів через YML, російські поля відсутні.
- **Зображення** – якщо немає прямих посилань на файли картинок, ставиться заглушка.
- **Бренд** – виправлено через примусову підстановку, але все ще може не застосовуватися через обмеження парсингу JSON.

## 3. Архітектура

```
index.html (UI)
   ↓
server.js (Fastify)
   ├── /api/upload – прийом файлу + полів, створення job
   ├── /api/jobs/:id – статус обробки
   └── /api/jobs/:id/download – скачування XML

jobStore.js – in-memory сховище задач
   ↓
processor.js – основний пайплайн:
   1. validateFields (артикул, назва, ціна)
   2. resolveImage (перевірка URL)
   3. resolveAvailability (наявність)
   4. generateProductContent (виклик ШІ)
   5. resolveCategory (підбір категорії)
   6. setItemResult (збереження результату)

aiClient.js – робота з ШІ
   ├── generateProductContent – основний запит (назва, опис, параметри, SEO)
   └── selectCategory – другий запит (вибір categoryId з кандидатів)

promptBuilder.js – побудова промптів

categoryDirectory.js – робота з prom_categories.xls
   ├── getTopLevelCategories – список 58 категорій
   ├── getBranchCandidates – пошук у межах гілки
   └── getCategoryCandidates – пошук по всьому справочнику (fallback)

xmlBuilder.js – збірка YML-фіду
```

## 5. Прийняті рішення

### 5.1. Артикул у назві
- **Рішення:** ШІ не повинен додавати артикул у назву. Артикул має бути тільки в полі `vendorCode`.
- **Виправлення:** оновити `promptBuilder.js` (змінити формулу назви).

### 5.2. Гнучкий маппінг колонок
- **Рішення:** у майбутньому навчити сервіс читати всі колонки файлу та передавати їх ШІ як додаткові дані.
- **Чому:** зараз ШІ не бачить колонки `колір`, `розмір`, `модель`, `вага` тощо, тому назви та параметри виходять неповними.
- **План:** додати в `applyMapping` збереження всього рядка, передавати в `generateProductContent` через `fileContext` або окремим полем.

### 5.3. Вибір категорії
- **Поточний підхід:** ШІ обирає верхній рівень (з 58), потім алгоритм шукає всередині гілки.
- **Проблема:** для категорії «Одяг» ШІ плутає дорослий та дитячий одяг, бо в списку немає окремої категорії «Дорослий одяг».
- **Варіанти вирішення:**
  - Уточнити контекст/тип товару через UI.
  - Додати ручний вибір категорії (випадаючий список у UI).
  - Розширити список верхніх категорій (але це ускладнить логіку).

### 5.4. Бренд
- **Рішення:** якщо бренд задано в UI – жорстко підставляти його, навіть якщо ШІ повернув `"No Name"`.
- **Реалізовано:** у `processor.js` додано примусову підстановку `globalBrand`.

### 5.5. Зображення
- **Логіка:** якщо URL не веде на файл картинки (немає розширення `.jpg`, `.png` тощо) – підставляється заглушка.
- **Чому:** для чистоти фіду, щоб уникнути битих посилань.

## 6. Відомі проблеми та способи їх вирішення

| Проблема | Причина | Вирішення |
|----------|---------|-----------|
| Худи потрапив у дитячий одяг | ШІ обрав верхню категорію «Дитячий одяг» через відсутність чіткої категорії «Дорослий одяг» | Уточнити контекст/тип товару через UI |
| Рубашка потрапила в обувь | Алгоритм пошуку підкатегорій знайшов найближчий збіг у неправильній гілці | Посилити пошук за ключовими словами або додати ручний вибір категорії |
| Бренд іноді не застосовується | ШІ повертає `"No Name"`, але примусова підстановка не спрацьовує через `vendor: generated.vendor` | Додано примусову підстановку в `processor.js` |
| У назві з'являється артикул | Промпт містить інструкцію додавати артикул у назву | Оновити `promptBuilder.js` – прибрати артикул з формули назви |
| Відсутні характеристики (колір, розмір) | Сервис не передає додаткові колонки ШІ | Реалізувати гнучкий маппінг колонок |
| Немає російської мови у фіді | Prom.ua не підтримує імпорт SEO-полів через YML | Заповнювати вручну або через API (не в пріоритеті) |
